# Authority fence and switch/rollback protocol (P7-3, #739)

Design, not yet implemented: everything below is target behaviour; "today" marks what the code does now. Source: `guides/rearchitecture_phase7_cutover.md` (P7-3, "Switch and rollback protocol"); `guides/rearchitecture_phase8_post_cutover.md` 8A entry. `engine/v2/ops/ARCHITECTURE.md` is over the 1000-line growth ceiling (frozen), so the contract lives here until a compression PR lets slices fold their part in. No tool here switches production: activation needs the standing session authorization and deployment permission (P7-5). Every drill is supervisor-run against a scratch or private target; owners never run them.

**Decision (owner, 2026-10-14, #739).** The rollback window is **10 completed sessions** after the switch. It sets the retention duration that the Phase 7 guide left to the release runbook; the Phase 7 guide is amended in this PR (its "another ten-session wait" sentence is about qualification, not retention). 8A may delete the legacy tree only after the window closes (see "Legacy catch-up").

**Standard tools.** None applies; there is no standard format here. Reused today: `engine/v2/ops/backup.py` (`run_backup`, `restore_backup`), `tools/v2_restore_drill.py`, `tools/v2_controlled_failure_drill.py`, `engine.v2.models.deployment.rollback` (#520), the promotion incumbent guard (#500), and the v2 `set_authority` compare-and-swap. New: the legacy `authority.json`/`authority.lock` fence (slice 1b) and the receipt format (JSON, hash-checked like the P7-1 manifest). One host, one SQLite catalog: a lock service is not needed.

## Invariant and fence

**At most one official writer** (exactly one once the switch completes; zero during a held or interrupted switch). At any instant at most one deployment (`legacy` or `v2`) may commit an official decision, settlement, ledger row, export or consumer-visible release.

1. **v2 side.** The fence is the existing `decision_authority` singleton (`engine/v2/ledger/decisions.py`: `owner`, `generation`; `set_authority(conn, expected_owner, owner, stamp)` is a compare-and-swap on `owner` (the owner is checked in Python inside the caller's write transaction, then updated; slice 1a adds `WHERE owner=?`) that increments `generation`). Today `decisions.insert` requires the caller's `owner` argument (default `catalog`) to match the authority row and is the check behind all official inserts (main commit and outcome import in `decision_commit.py`, history import); `_require_catalog_authority` (`decision_commit.py`) guards only the supersede path; `_set_authority_once` (`ledger_history_import.py`) sets `catalog` from any owner, including `v2`. Slice 1a changes this: an *official* insert/commit requires owner `v2` and the generation captured in the job record (captured at creation, compared again inside the commit transaction), so a zombie from generation N cannot commit under N+1. Before S5, v2 makes no official commits; shadow runs, drills and the S2b history import are non-official and run under `catalog`, `none` or the scratch-only `drill` value. After S5 the official catalog accepts every insert, official or not, only with owner `v2` (slice 1a enforces this; non-official work such as shadow runs must use its own scratch catalog, #740), so every decision row above the boundary rowid is official and B2 selects by rowid.
2. **Legacy side.** Two files in the retained legacy data root: a stable coordination lock `authority.lock` (never replaced) and `authority.json {owner, generation}`. Every legacy writer of official rows, exports or bundles takes a shared `flock` on `authority.lock`, reads `authority.json`, checks `owner == "legacy"` (the only exceptions are B3's reconcile append and the S2b `--repair-tail` truncation, which run under the exclusive lock, B3 with owner `none` and the generation checked, the truncation with owner `legacy` while the S2 drain holds all writers off), records the generation at start, re-checks it under the lock before each append, and holds the lock through the guarded write. `fence`/`grant` take the exclusive lock, then replace `authority.json` by atomic rename. The scheduler wrapper reads `authority.json` at each start (not its environment). Until slice 1b lands the legacy scheduler is fenced only by disabling it, which the drill treats as insufficient.
3. **Transfer is fence, verify, grant.** Fence the current writer, verify it, only then grant the other. A crash between leaves **zero** writers (writes held, last validated read release served), never two. `fence` and `grant` take `--side catalog|legacy`; `--side` is a required argparse choice (a missing or unknown value is rejected by argparse); `AUTHORITY_SIDE_INVALID` is the typed refusal for a valid choice used with the wrong command or state (e.g. `fence --side catalog` on the legacy-only path). **Other-side precondition:** `grant --side catalog` (not `--check-only`, which skips this check because legacy is still `legacy` before the fence) reads the legacy `authority.json` (safe open; the file and its `AUTHORITY_FILE_INVALID` refusal are slice 1b's, so this check is wired when 1b lands, like the mark check for slice 2) and refuses `AUTHORITY_FENCED` unless its owner is `none`; `grant --side legacy` refuses `AUTHORITY_FENCED` while the catalog owner is `v2`. Neither writes anything on refusal.
4. **Owner values and transitions.** Catalog owner values: `drill` (scratch only; today written only by the P6-5 check `checks/rearchitecture_phase6_restore_drill.py` in a scratch catalog; never on the official catalog), `catalog` (set by `ledger import-history` when it processes a non-empty included prefix; non-official v2), `v2`, `none`, or no row on a fresh catalog. S2b records the post-import owner and generation in the boundary receipt; S5 passes exactly that owner as `expected_owner` (`catalog -> v2`, `none -> v2`, or `None -> v2` creating the row). Backout B1 sets `v2 -> none`. Legacy file: starts `{legacy, 1}`; fence writes `{none, n+1}`, grant writes `{legacy, n+2}`. The two generations are independent.
5. **Bounds and file safety.** Every wait is bounded (default 300 s) and refuses `AUTHORITY_LOCK_TIMEOUT`, leaving authority unchanged for `fence`/`grant` lock acquisition and a legacy writer's `flock` acquisition; B1's wait for in-flight v2 jobs times out after the fence, so its end state is owner `none` and zero writers (see B1). `fence` and `grant` first read owner and generation and are idempotent: already at the target state is a no-op; a state that is not the command's legal predecessor refuses `GENERATION_MISMATCH`. Legal predecessors: `fence --side legacy` from `{legacy, n}` to `none`; `grant --side catalog` from the post-import owner recorded in the S2b receipt (`catalog`, `none` or no row) to `v2`; `fence --side catalog` from `v2` to `none`; `grant --side legacy` from `none` to `legacy`. `grant --side catalog` takes `--switch-id` and reads the S2b boundary receipt, so its `BOUNDARY_STALE` check depends on slice 2 (slice 1a ships the owner/generation check; the mark check is wired when slice 2 lands). A missing `authority.json` or `authority.lock` refuses `AUTHORITY_FILE_INVALID` and only `init` creates them (fail closed) (the CAS itself would raise on an owner mismatch). Operator kill path for a stuck holder: read the pid that the exclusive holder (fence, grant, B3, S5 re-check) writes into `authority.lock` on acquire (shared writer holders write no pid; a stuck legacy writer is stopped through its own job or schedule controls), stop it with the normal process signal, rerun the step (a killed legacy appender may leave a torn trailing ledger line; S2b's torn-line rule below handles it). The pid read from `authority.lock` is capped at 4 KiB (oversize refuses `AUTHORITY_FILE_INVALID`). Every authority, lock, receipt and staged artifact open is `O_NOFOLLOW|O_NONBLOCK` then `fstat` regular-file, with a cap (receipts and `authority.json` 64 KiB; staged batch, divergence artifact and raw drill output are streamed and hashed, capped at 256 MiB, as are legacy ledger files, and every legacy ledger read (S1 capture, S2b, the S5 re-check, B3's divergence preflight) uses the same safe open; backup manifest comparison reads at most 1 MiB; backup database and artifact opens in `run_backup`/`restore_backup` check the size against the manifest-recorded size before reading, stream-and-hash, and have a 4 GiB hard cap per file); one code per condition: an unsafe or over-cap staged batch, divergence artifact, raw drill output, backup manifest or backup database/artifact file refuses `ARTIFACT_INVALID`; a backup whose manifest or file hash does not verify keeps the existing `INTEGRITY_FAILED` of `restore_backup` (`engine/v2/ops/backup.py`, unchanged); a missing backup, copy, restore target or prior receipt refuses `PRIOR_RECEIPT_INVALID`; an over-cap legacy ledger file refuses `IMPORT_INPUT_TOO_LARGE` and a symlink, FIFO or non-regular one refuses `IMPORT_INPUT_UNSAFE` (slice 2; these two codes apply to every legacy ledger read: S1 capture, S2b, the S5 re-check and B3's divergence preflight, each refusing before any state change and writing no receipt (S2b pre-checks every legacy file before the first per-file import commit; the same safe-open and size-cap rule also covers every legacy ledger open for write, the B3 append, the repair-tail truncation and the B3 sidecar read)); an unsafe or malformed receipt refuses `PRIOR_RECEIPT_INVALID`; `AUTHORITY_FILE_INVALID` is only for `authority.json` and `authority.lock` (the wrapper then fails closed). `restore_backup` (`engine/v2/ops/backup.py`), reused by S4, reads the manifest, database and artifacts unbounded and without these checks today; slice 2 enforces the caps, `O_NOFOLLOW|O_NONBLOCK` opens and `fstat` checks inside `restore_backup` itself, so every caller (`tools/v2_restore_drill.py`, `tools/v2_controlled_failure_drill.py`, the S4 adapter) gets them; the backup directory's manifest, database and artifact opens are covered by this invariant. Staged batches and sidecar records are written with the same temp-then-replace helper as receipts.
6. **Receipts.** Each step writes one immutable JSON receipt (step, authority generations before/after, marks, input hashes, result: counts and hashes only) as `<ops_root>/cutover/<switch_id>/<seq>-<step>.json` with the existing write-once atomic artifact write; a retry writes the next `seq`; there is no mutable log. `switch_id` (UUID) is minted once by `ops cutover capture` and reused on every retry. Long lists (the S2b divergence list) are separate hashed artifacts the receipt references.

Commands: `python3 -m engine.v2.ops cutover authority {init,status,fence,grant} --side …` (1a catalog, 1b legacy; `init --side catalog` writes no catalog row (a fresh catalog is "no row", per the owner values; S5 creates it) and only checks the catalog is reachable, and `init --side legacy` creates the `{legacy, 1}` file, both before S1); `status` is read-only and is the only authority command drills use to observe.

## Switch protocol (forward)

Each step is idempotent on `switch_id` and refuses to start if the previous receipt is absent or no longer verifies.

### S2b semantics

S2b is not read-only; it runs `ops ledger import-history`, which commits per source file. A mid-import failure leaves earlier files committed, writes no boundary receipt, and S3-S5 refuse without one; S2's effects (schedule disabled, drained) stay until S2b is rerun or the operator abandons the switch with `ops cutover backout resume` (slice 6; B5 before S5). Retry is idempotent by source hash and line. One rule for first switch and re-switch: repeated legacy rows that differ from catalog rows still import and are recorded as divergences (standing 2026-09-14 rule) and listed in the boundary receipt, never blocking (S2b imports with divergence recording, so a conflicting legacy duplicate does not raise at `decisions.py:282`; an import provenance conflict, the same source line with different bytes, still raises the untyped `DecisionConflict("import provenance conflict")` at `decisions.py:269`, which `ledger_history_import.py` already maps to `IDEMPOTENCY_CONFLICT`); what refuses is a post-import line-accounting or tail-hash mismatch (`LEGACY_IMPORT_MISMATCH`), an over-cap legacy file (`IMPORT_INPUT_TOO_LARGE`, checked before reading) or `IDEMPOTENCY_CONFLICT`. On a re-switch, B3-exported lines re-imported here are matched to catalog rows by decision id and payload hash; a mismatch is a recorded divergence. The import sets owner `catalog` only for a non-empty included prefix (`--through`). **Torn-line rule:** a legacy file whose last line is unterminated and not valid JSON (a killed appender) refuses `LEGACY_IMPORT_MISMATCH` (today the importer raises the generic `VALIDATION_FAILED` for any non-JSON line, `ledger_history_import.py`; slice 2 types it); the operator truncates exactly that verified tail with `ops cutover capture --final --repair-tail` (slice 2, which first copies the removed tail to a private diagnostic, then records its hash in the receipt; a non-JSON line anywhere else in a legacy file has no repair and refuses `LEGACY_IMPORT_MISMATCH`) and reruns S2b.

## Backout (rollback)

**Triggers** (Phase 7 guide): unexplained economic drift, missing population, duplicate authority, unreconciled decisions, unrecoverable publication, missed session deadline. If facts cannot be reconciled, hold writes (authority stays with nobody) and keep serving the last validated read release. Backout never restores an old database over new official facts, never deletes a v2 row, and never lets the old scheduler repeat a completed decision.

| # | Step | Command |
|---|---|---|
| B1 | Fence v2 first: `set_authority(conn, "v2", "none", stamp)`; then wait (bounded) for in-flight v2 jobs to finish; on timeout refuse `V2_JOB_WAIT_TIMEOUT` with the state stated plainly: owner already `none`, zero writers, the stuck job still running (its commits are refused `AUTHORITY_FENCED`: the owner check fires first), and the retry is the same command after the operator stops the job (the fence is a no-op the second time) and the operator stops the job via normal job controls; verify with `status` | `ops cutover authority fence --side catalog` (slice 1a); needs no prior receipt, only owner `v2` and `--expected-generation`; once the tenth S8 receipt exists it refuses `ROLLBACK_WINDOW_CLOSED` before any write (slice 6 wires the check into this command) |
| B2 | Recapture v2 marks and diff against the boundary receipt's post-import marks: the reconciliation set is the decision rows above the boundary `sequence` (after S5 the official catalog takes inserts only with owner `v2`, so such rows are official) | `ops cutover capture --diff` (slice 2) |
| B3 | Reconcile: export each reconciliation row in the legacy ledger format and append under the exclusive `authority.lock` (B3 is the privileged path that appends while the file owner is `none`, checking owner `none` and the generation under the lock). The staged batch is first written as a hashed file; before any append B3 re-hashes it (`BATCH_HASH_MISMATCH`) and preflights the whole batch for divergences; lines are appended; then a completion record with the batch hash and the hash of the lines actually appended goes to a separate sidecar file (never into the prediction/outcome JSONL, whose readers parse every line as a ledger record); the receipt follows. Recovery applies the S2b torn-line predicate (unterminated, non-JSON last line only), copies the removed tail to a private diagnostic, records its hash in the sidecar, truncates it, re-hashes the staged batch (`BATCH_HASH_MISMATCH`), runs the same whole-batch divergence preflight and compares the payload hash of every id already present (a differing payload is a divergence, not a skip), then replays, appending only ids not present. A v2 decision is never voided. A divergence against the legacy ledger is recorded in `decision_divergences` and stops the rollback for the operator (`RECONCILE_DIVERGENCE`) | `ops cutover backout reconcile` (slice 6) on `engine/v2/ledger/export.py` |
| B4 | Grant legacy: write `authority.json` with the next generation and `owner: "legacy"`, only after B3's receipt verifies | `ops cutover authority grant --side legacy` (slice 1b) |
| B5 | Re-enable the legacy schedule; switch consumers back; keep v2 read-only | `ops cutover backout resume` (slice 6); also the pre-S5 abandonment path, with no B1-B4 precondition, where it also unpauses non-official v2 writers; if the legacy file is `none` (interrupted S5) it first runs `grant --side legacy` from `none` |
| B6 | Verify as S8 against legacy; the v2 catalog stays as evidence | `ops cutover verify --side legacy` (slice 6) |

## Legacy catch-up

Rollback at session `k` of the window means legacy missed sessions 1..k while v2 was official. The old scheduler resuming is not a catch-up.

1. **Missed decisions come from v2.** B3 appends them; the legacy writer refuses to emit a decision for an `as_of` already in the ledger. Today's guard in `engine/ledger.py` refuses only a clashing `row_id`; the `as_of` refusal is new, added to the wrapper in slice 1b.
2. **Settlements.** Positions opened by v2 decisions that mature later are settled by the legacy settlement run; outcomes v2 already settled arrive via B3, keyed by decision id, so nothing settles twice.
3. **Sessions where v2 committed nothing** stay missed and are listed in the receipt as `no_official_decision`. This is new rollback behaviour: legacy backfill is on by default and would call `ledger.snapshot` for missed nights (`engine/dashboard/nightly.py`). Slice 6 suppresses backfill for those sessions (a skip set read by the wrapper) with a regression control: after B5 a legacy run writes no row for such a session.
4. **State and caches.** The legacy tree is not mutated during the window except by B3 (and its recovery truncation), so it is stale by exactly the missed sessions; the first legacy run after B5 refreshes incrementally and B6 verifies freshness. B3's receipt records staleness so an unrefreshable gap is a blocker the operator sees before B4.
5. **Window close.** One event: the S8 receipt verifying the tenth completed session after the switch. A backout before it exists is allowed; once it exists `ops cutover backout` refuses `ROLLBACK_WINDOW_CLOSED`.

## Failure semantics (R1-R6)

Each step inherits the column of its family. Refusal checks run before a step's side effects.

| | Capture/drain/backup/verify (S1-S4, B2); S2b see above | Fence moves (S5, B1, B4) | Start/switch/verify (S6-S8, B5, B6) | Reconcile (B3) |
|---|---|---|---|---|
| **R1 missing input** | Missing or unverifiable prior receipt, backup, copy or restore target refuses `PRIOR_RECEIPT_INVALID`; no state changed | S5/B4: missing prior receipt (`PRIOR_RECEIPT_INVALID`); B1: no receipt, owner/generation only; any `status` mismatch (`GENERATION_MISMATCH`) refuses; no authority write | Missing release, pointer or receipt refuses | Missing export or legacy ledger refuses |
| **R2 cache** | None; reads are live or hashed artifacts | None; `status` reads live | ETags compared, never trusted from memory | None |
| **R3 retry** | Re-running recaptures; a new receipt is appended, earlier kept; a changed mark is reported, not merged | Resumes from the observed owner/generation; never grants if the other side is not verified fenced (`AUTHORITY_FENCED`, see item 3) | Retried by `switch_id`; the schedule starts at most once per generation | Re-runs the diff, appends only missing ids |
| **R4 transaction** | Backup atomic by its own contract; capture is one read transaction | `set_authority` is one catalog transaction; `authority.json` is an atomic rename | Pointer swap is `os.replace`; schedule start is one enable | Staged-batch + sidecar boundary (B3); receipt after the sidecar record |
| **R5 partial write** | Partial backup not accepted: completeness is the verified manifest, published last; partial scratch removed or kept as diagnostics | A crash between fence and grant leaves no writer; `status` detects it and per `status`, `grant --side catalog` finishes it or `grant --side legacy` (legal from `none`) reverses it | After a pointer swap but before the receipt, `verify` first completes or confirms the retained publication's durable acknowledgement (release row, outbox, watermarks) then records success; no second swap | Torn line or some ids appended; recovery truncates and replays; rows never deleted |
| **R6 idempotency** | `switch_id` + step keys the receipt; rerun is a no-op when hashes match | Re-fencing a fenced writer or re-granting a granted side is a no-op; a grant to the wrong generation refuses `GENERATION_MISMATCH` | As S5 | Keyed by decision id; duplicate append is a no-op, differing payload is a divergence and stops |

Cross-cutting: no receipt, log or artifact carries a local path or raw exception text (`ARCHITECTURE.md` §5); the typed code and operation id locate the private diagnostic.

**Typed codes** (defined once, owner slice in parentheses): `AUTHORITY_FENCED`, `AUTHORITY_GENERATION_STALE` (shared: defined in 1a for catalog/publication/export, reused by 1b for legacy writers; not retryable); `AUTHORITY_LOCK_TIMEOUT` (1a catalog waits, 1b legacy flock); `AUTHORITY_FILE_INVALID` (1b), `BOUNDARY_STALE` (defined in 1b; raised for the legacy count/tail-hash mismatch by 1b and for the catalog-mark mismatch by slice 2's wiring in `grant --side catalog`; slice 1a ships only the owner/generation check, with `--expected-owner` and `--expected-generation` flags), `V2_JOB_WAIT_TIMEOUT` (1a; B1's wait for in-flight v2 jobs; retryable after the operator stops the job); `ARTIFACT_INVALID` is not a registered failure code today (its only emitter is the inference-result reason at `engine/v2/models/loader.py:61`; `FAILURE_CODES` in `engine/v2/contracts/operations.py` has no row), so slice 2, the first to use it, registers it there with its retryable flag (not retryable); every new v2-side code in this list is registered in that file by its owner slice, while the legacy-side codes (`AUTHORITY_FILE_INVALID`, and the legacy uses of `AUTHORITY_FENCED`, `AUTHORITY_GENERATION_STALE`, `AUTHORITY_LOCK_TIMEOUT`, `BOUNDARY_STALE`) are declared in a legacy-owned table with the same strings, because legacy code cannot import `engine.v2` (root `ARCHITECTURE.md` §3), as are the codes below: `GENERATION_MISMATCH` (S5 CAS owner/generation mismatch, replacing the untyped `DecisionConflict`; 1a; not retryable), `PRIOR_RECEIPT_INVALID` (missing/unverifiable receipt, backup, copy or restore target; slice 2; not retryable), `AUTHORITY_SIDE_INVALID` (a valid `--side` used with a command or state that does not support it; argparse itself rejects a missing or unknown value; 1a; not retryable). Slice 6 reuses `ARTIFACT_INVALID` (it depends on slice 2); `IDEMPOTENCY_CONFLICT` is existing (`engine/v2/ops/submission.py`); retryable flags: `AUTHORITY_LOCK_TIMEOUT`, `DRAIN_TIMEOUT` and `V2_JOB_WAIT_TIMEOUT` retryable after the operator clears the holder or job, every other code here not retryable; `LEGACY_IMPORT_MISMATCH`, `IMPORT_INPUT_TOO_LARGE`, `IMPORT_INPUT_UNSAFE` (2); `DRAIN_TIMEOUT` (3); `BATCH_HASH_MISMATCH`, `RECONCILE_DIVERGENCE`, `ROLLBACK_WINDOW_CLOSED` (6). Registration: `GENERATION_MISMATCH` and `AUTHORITY_SIDE_INVALID` are registered in `FAILURE_CODES` by 1a and `PRIOR_RECEIPT_INVALID` by slice 2, each mirrored in the legacy-owned table by 1b. Malformed `--expected-owner`, `--expected-generation` or `--switch-id` values are rejected by argparse type checks before any state is read (no typed code). The supersede guard `_require_catalog_authority` (`engine/v2/ops/decision_commit.py:307`)'s current `VALIDATION_FAILED` (not the separate "already superseded" refusal) becomes `AUTHORITY_FENCED`.
