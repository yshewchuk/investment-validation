# SIZE season heat: population read, storage and HMOS (design)

Design only; slice 1 is `engine/v2/research/season_heat.py` (#2344). Contract text moves to `engine/v2/research/ARCHITECTURE.md` with the code slices; slice list is in PR #2357.

Design only (#2355 context): no code reads population outcome labels yet. The qualified panel builder owns the read; the `research_eligible_history` table, recipe and `comparison_inputs` are unchanged, and its context and receipt identities move only through the installed-producer source hash (moved helpers), never through contents; existing history snapshots are rebuilt (clean contract change, no compatibility transition). A new `season_population` module has `plan_roster` (bounds metadata only, at context derivation; opens no outcome) and `read_labels` (value build only). The anchor lookup, table-wide outcome fragment index and exact anchor-to-fragment binding move out of `eligible_history` into `outcome_binding` unchanged, so H11 and the population share one implementation.

**Population and targets.** Labels come from `load_population` under the history context's `as_of_month` and purpose, so holdout memberships are never planned, opened or counted; the stored-outcome reader's isolation check still applies. Window: event dates from 251 sessions before the earliest decision session through the latest decision date. A label's availability is its anchor `post_close_date` plus one calendar day, which the stored outcome must repeat exactly. Targets are every `(event_id, decision_session)` clock of the history context; the decision date is that clock's `source_session_ceiling` from `forecast_cutoff` (horizon 1 is AMC E-1 close and BMO E-2 close; horizons 3 and 5 are earlier). Own-ticker exclusion stays in `compute_season_heat`. Embargo groups (same-ticker training overlap) are not applied to other tickers' labels; the target's ticker is excluded, so no own-ticker overlap can enter. This is a design judgement for review, not a measured result.

| Population condition | Outcome |
| --- | --- |
| No bounds row for the event | Excluded `missing_native_bounds`, counted; the bounds contract has "one row per produced outcome", so no row means no produced outcome and no label exists. The count is in the receipt (a typed, visible shortfall, not a silent one); whether a producer-failure threshold should refuse is decided from the first authorized data run's counts. |
| Bounds row with both dates null | Excluded `null_source_bounds` (unavailable label; object never opened). |
| Event date not a trading session | Excluded `off_session_event_date`, counted, before `compute_season_heat` sees it. |
| Availability after the latest decision, or event outside the window | Not planned or opened; no exclusion. |
| One null bounds date, invalid bracket or session mismatch; duplicate bounds row for one `(ticker, event_date)` | `CONTRACT_MISMATCH` before any outcome opens. Separately, two canonical events sharing `(ticker, event_date)` never reach the roster: `load_population` removes them as ambiguous without refusing. |
| Fragment missing, `row_count != 1`, key, partition or time mismatch, or object id/hash differing from the anchor | `HOLDOUT_ACCESS_DENIED`. |
| Two `computed_moves` fragments for one key anywhere in the table | `HOLDOUT_ACCESS_DENIED` (whole-table check, as H11). |
| Outcome `skipped`, or availability null or not post_close + 1, or event date differs, though bounds are non-null | `CONTRACT_MISMATCH` at value build: bounds contract "null bounds for every unavailable label", so a contradiction is a source defect. |
| Invalid or non-finite `abs_move` / decision session not a trading session (targets are product, never excluded) | `EXPERIMENT_VARIANT_FAILED` / `CONTRACT_MISMATCH` respectively. |

**Receipt and identity.** The panel context (`magnitude_panel_context.v5`) carries `season_heat_population.v1`: `as_of_month`, window, calendar source, counts, exclusion counts per reason, `exclusions_digest`, `roster_digest` over retained `(event_id, outcome_object_id, outcome_content_hash, available_as_of_date)` and at most 10 sample ids. Content-hashed objects bound by anchors make the roster digest bind label values without opening them; no per-event roster is stored, which bounds the context size. The context's `feature_recipe` becomes `recipe("HMOS")`. No coverage threshold: counts are reported, and materiality is measured by the first authorized data run.

**Storage.** Panel table `research_magnitude_panel` contract `.v3` becomes `.v4`: five columns `season_heat_mean_abs_5|20|60`, `season_heat_count_20` (int, the actual qualifying count even below the mean threshold), `season_heat_ratio_20_252`, nullable except the count, plus a `season_heat` lineage block holding the receipt id. Contexts, row ids and snapshots move; older sealed plans re-prepare, with no compatibility reader. Dictionary hashes for `H`, `HM`, `HMO`, `MO-` and `M` are byte-identical, so the v9 dictionary hash and every v1-v9 request and candidate id are unchanged. New `HMOS` is `HMO` plus a `season` block (appended last, `season_population` dependency) with its own hash; recipe and `model_columns` follow `HMO`, including `has_implied_quote`.

**Request and cost.** Request `v10` requires the `HMOS` dictionary hash and allows `H/HM/HMO/MO-/M/HMOS` in that order; v9 behaviour is unchanged. Heat is one `read_labels` pass (one scan per retained label, batched by ticker) and one forward sweep of `compute_season_heat` over deduplicated `(event_id, decision_session)` pairs, with O(1) work per target after window advance. R1: memory is the retained labels, 252 session buckets and one result record per deduplicated target; no per-target label copies. R2: nothing cached across builds. R3: refusals above. R4: nothing persisted before panel publication; a failure publishes nothing. R5: no retry. R6: equal pinned inputs give equal receipt, values and context id.
