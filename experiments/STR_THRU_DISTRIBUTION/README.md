# STR-THRU distribution research

[DESIGN.md](DESIGN.md) defines the four approved implementation bundles and scientific controls. [ARCHITECTURE.md](ARCHITECTURE.md) documents fitting/results, causal residuals, the fixed child and run metadata plus D4's source-free scoring/report contracts; public modules remain in the parent `experiments` package.

- A supplies magnitude histogram math and frozen payoff controls.
- B supplies separate native ownership, source/fold admission, raw-pair budgets and claims.
- C adds admitted numeric fit receipts and earlier-OOF residual controls; raw probabilities remain explicitly uncalibrated.
- D supplies explicit economics, research books, paired/forecast reports, pinned quote/bridge adapters, bounded fixed-child fits and metadata seals. The [contained runner](ARCHITECTURE.md#explicit-contained-runner) and operator below add one explicit bounded attempt, not automatic real-run authorization.

Focused synthetic checks live in `tests/v2/research/test_distribution_*.py`. No real data, provider, final-holdout, deployment or automatic run authority follows from these APIs. Shared platform owners retain source eligibility, transport and holdout policy.

The runner requires the complete `{1,3,5}` outer result roster before evaluation, derives book/quote alpha keys from the sealed policy, and discards failed invocation state without retry. Zero funding is not risk sufficiency or promotion evidence.

`DistributionRunPlan` is the metadata/section-journal interface, not an executable runner. Its [run metadata and containment contract](ARCHITECTURE.md#run-metadata-and-containment) specifies artifact reads, explicit writes, partial-seal behavior and dedicated-process prerequisites. Each preflight reuses the request validator before metadata/artifact access and returns a detached policy: editing returned metadata cannot mutate the instance's request, and an invalid owned request refuses `INVALID_EXPERIMENT_SPEC`. `contained` rejects malformed resource limits and nonpositive, nonfinite or nonnumeric remaining duration before process-state access or watchdog startup; positive fractional seconds are supported. Preflight/collection do not install containment automatically or certify resource feasibility.

Journal slots and section names must be nonempty strings. Appended bodies are dictionaries; section rows are mappings, with `position` reserved for the publisher. Completed records must contain a run-plan ID and named section descriptors. Shared manifest-builder validation checks descriptor metadata before a completion write and on read, without artifact I/O. Before append, the ID must equal the existing verified journal seal's ID; missing seals or mismatches refuse `INVALID_EXPERIMENT_SPEC`, leaving the immutable slot available for correction. This adds only a seal read, not repeated admission or report-shard reads. Malformed caller inputs/metadata use the same refusal; shared size limits and CAS verification retain native resource/integrity errors. Collection still reverifies admission and shard bytes. This does not authenticate execution or extend completion authority.

## Fixed CAS worker

Both in-process fit and fixed child first call `validate_fit_output` to validate raw numeric results against the recipe, ordered matrices/labels/events and the shared result contract. It returns ordered rows; identity mismatches retain `EXPERIMENT_IDENTITY_CONFLICT` and histogram checks retain their native data error. `publish_fit_output` then receives these supported rows, a shared empirical/unresolved tail and diagnostics. Forecasts are event-key sorted; excess order/duplicates remain intact. It uses existing CAS sections and bounded-cadence stderr progress; it does not validate admission, grant a retry or write the completion journal. Native CAS failures propagate; a failed later publication can leave complete unreferenced CAS objects.

The installed `python -m experiments.distribution_worker` is an internal protocol, not a public experiment CLI. A launching adapter must supply its private header path and explicit resident-memory/CPU/affinity limits (the shared VmRSS watchdog, not RLIMIT_AS), enforce wall/stdout/exit bounds and validate results before journal completion. Before OS calls, the child requires positive bounded plain-integer memory/CPU limits and a plain-integer `cpu_id` in `[0, 2**31 - 1)`. An unavailable CPU still returns sanitized `RESOURCE_UNAVAILABLE`. After containment, it requires a mapping header and validates its supplied recipe through the existing canonical recipe owner before reading recipe fields. It then checks plain declared horizon, unique string event axes/present projected rows and a nonempty store-root string; these are protocol shape checks, not source eligibility or path-security proofs. It caps its header/output document using the existing record limit, reads admitted feature/training shards only, uses the installed fixed native pair and writes a result document to CAS. stdout contains one compact artifact descriptor or sanitized typed failure; unexpected exceptions map to `RESOURCE_UNAVAILABLE`. No catalog, provider, fresh outcome, holdout policy or production path. This slice supplies no general launcher, automatic retry, experiment attempt or claim of calibrated probabilities.

## Bounded admitted fit

`DistributionFits.fit(..., bounded=False)` preserves C's default. Explicit `bounded=True` uses the sealed B child limits, claims the trial first and binds plan/worker/limits before launch. Bounded completion persists that binding in required `execution` under `distribution_fitted.v2`. Every `read` or completed `fit` replay verifies it and the required journal marker against the admitted plan/fixed worker before result shards, even when `bounded=False`; missing/changed evidence refuses without retry. Unbounded v1 retains its exact shape, cannot have a bounded marker and cannot attest bounded execution; `bounded=True` cannot relabel it. `distribution_execution.run_distribution_fit` is the fixed Linux launcher over an admitted CAS source/recipe/event axis/horizon: single CPU, one-thread minimal environment, explicit resident-memory/CPU/wall ceilings, 30-second wait progress and at most 4 KiB stdout. It always reaps the child and cleans its private header. No arbitrary estimator or command injection API.

The parent requires successful exit, verified CAS output and exact expected recipe/matrices/event axes/result diagnostics before immutable completion. Failure/interruption leaves an unfinished claim, not a retry. Only actual completed fits publish success. The existing plan source closure explicitly includes the subprocess worker, since a module-name string is not a static import; changing only child bytes invalidates old seals before new admission. This reuses the established implementation identity, not another provenance framework. The launcher handles one child, not experiment-wide CPU/deadline/admission or real-run authorization.

## Causal pipeline

`distribution_pipeline.evaluate_outer` freezes every sealed alpha's D-1 intentions before D0/D+1 quotes or centrally admitted outer targets are read. `finish_reports` publishes conditional funded-book, profit and all-horizon forecast sections using the unchanged selector, costs and missingness rules. Both require a matching durable run seal before effects and consume its detached policy; changing the live request or supplied evaluation plan refuses before evaluation/report work. Any already-recorded group intent, including partial alpha prefixes, refuses before readers, publication or accumulator mutation; other failures still require discarding failed invocation state without retry. These library functions neither fit nor orchestrate a run; an executable runner remains separate. See the [causal pipeline contract](ARCHITECTURE.md#causal-outer-pipeline). Native synthetic integration covers actual catalog/panel admission, six raw-pair fits, earlier OOF pools, CAS quote fragments, the central target reader and final report; it does not qualify real-study resources or inputs.

## Operator lifecycle

Run `python -m experiments.distribution_run --help` in a dedicated Linux main-thread process; do not embed this lifecycle in a thread pool or reuse a failed process. Every action requires explicit inputs and `--no-ledger`; there are no resource, economics, source or strategy defaults. This reuses SUPER SIZE's native source preparation/registration and metadata I/O, **not** its 33-candidate SIZE search or target-specific budgets. Prepare the qualified, all-5/3/1-horizon SIZE source registration and sealed plan through its existing lifecycle first; no SIZE model run is required. Do not change a registered checkout's source files: closure drift requires fresh registration and seals, never migration.

Inputs are existing JSON objects (bounded to 16 MiB each), an existing catalog and store:

- `--spec`: a distinct native experiment spec with runner `experiments/distribution_run.py`, seed zero, `computed_moves`, empty economics/input files and outer folds matching the source. Distribution economics belong exclusively in the run request.
- `--source-spec`, `--source-request`, `--source-plan-ref`: the registered SIZE spec, exact source search request and the sealed plan's ArtifactRef, not copied panel rows or a distribution plan reference.
- `--recipe`: the unchanged document from `distribution_candidate_recipe.candidate_recipe` for the explicitly chosen H/HM/HMO feature set.
- `--budget-caps`: exactly `max_fits`, `max_trees`, `child_limits`; the latter supplies positive integer `memory_bytes`, `cpu_seconds`, `wall_seconds`. Counts include all actual inner/outer raw pairs at 5/3/1; child memory cannot exceed the parent request ceiling.
- `--request`: the complete closed `distribution_run_request.v1` [policy contract](../README.md#distribution-explicit-policy), including explicit economics/book/uncertainty/risk/resource limits, quote snapshot, frozen pre-cutoff payoff ArtifactRefs for every alpha/year, and optional causally frozen benchmark refs. Native standard contracts/reconstructed quote availability remain explicit limitations. Strict benchmark policy requires full coverage; absence otherwise means unavailable, not inferred superiority.

For example, after independently qualifying the intended input documents and budgets:

```bash
args=(--spec distribution-spec.json --source-spec size-source-spec.json
      --source-request size-source-request.json --source-plan-ref size-plan-ref.json
      --recipe distribution-recipe.json --budget-caps distribution-fit-caps.json
      --request distribution-request.json --catalog /path/to/catalog.sqlite
      --store-root /path/to/store --no-ledger)
python -m experiments.distribution_run prepare "${args[@]}"
python -m experiments.distribution_run register "${args[@]}"
python -m experiments.distribution_run preflight "${args[@]}"
python -m experiments.distribution_run seal "${args[@]}"
# Only after bounded-run authorization and resource/input qualification:
python -m experiments.distribution_run run "${args[@]}"
python -m experiments.distribution_run collect "${args[@]}"
python -m experiments.distribution_run report "${args[@]}"
```

`prepare` returns recomputed own/source identities and conservative raw-pair counts without SQL/CAS writes. `register` repeats that native preparation and reserves the distribution owner; it does not certify bridge/benchmark coverage or resource feasibility. `preflight` verifies those actual run dependencies after registration, without SQL/CAS writes. `seal` explicitly writes immutable B/D metadata; a later refusal can leave a B seal. `run` alone starts fits/outcome work; failed or interrupted attempts stay claimed with no retries or repair. An exactly completed `run`, `collect` and `report` only verify/read the saved report. Run first probes completion read-only; only absence permits writable reopen/revalidation, without resetting its deadline. SQLite WAL read coordination may create/update sidecars; replay does not switch journal mode or ignore committed WAL. Missing/unreadable input documents and missing/null required spec fields refuse as invalid experiment input, storage outages remain resource failures, and raw CAS corruption retains integrity failure. See [failure/containment contract](ARCHITECTURE.md#distribution-operator).

All actions validate/detach the request before indexing limits or opening storage, then apply its declared parent/job bounds before catalog or metadata traversal; request bootstrap time counts against the same deadline, and `run` does not reset it. These bootstrap limits are caller-declared, not authenticated against a saved seal until admission; a changed valid request refuses before started claims/fits but can already have governed pre-admission I/O. Progress, including inherited native logs, goes to stderr; stdout is one bounded JSON result or `{ "refused": <typed problem> }` with exit status 2. These synthetic tests prove wiring, not real-data/provider/final-holdout permission, capacity or measured RSS feasibility: `test_distribution_run_native.py` and `test_distribution_cli_native.py` exercise real bounded children and replay without a private dataset.

Treat every nonzero process exit as terminal: never repair an attempt, reuse its in-memory state or retry its started identity. Failure-journal I/O preserves the original execution error and emits only a fixed best-effort secondary diagnostic on stderr; a failure record may be absent, but its absence never releases a started claim. Containment setup/cleanup failure can retain a stricter CPU ceiling and likewise permits no continued execution. Complete `{1,3,5}` results and sealed alphas are checked before evaluation; zero-funded diagnostic flags are not risk sufficiency, capacity, promotion or superiority evidence.
