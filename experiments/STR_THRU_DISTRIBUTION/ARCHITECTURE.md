# Distribution fitting and causal controls

Research-only Bundles C/D extend the [experiment design](DESIGN.md) and the [B admission contract](../ARCHITECTURE.md#distribution-native-admission). The explicit local operator grants no production path, provider read or final-holdout authority. C's default remains in-process; the runner selects bounded children and dedicated-process containment. Real execution needs separate user authorization.

## Public boundary and dependencies

| API | Caller, input and output |
| --- | --- |
| `distribution_candidate_fit.fit_candidate(recipe, train_features, train_labels, prediction_features, *, columns)` | Numeric adapter/tests supply exact recipe, ordered columns and matrices; returns raw histogram rows, one shared training-only tail, matched points and diagnostics. |
| `DistributionTrials.read_fit_context(role, outer_year, inner_year=None)` | C obtains freshly verified plan, native fold, admission and projected stored training/features; no second outcome read or eligibility policy. |
| `DistributionFits(trials).fit(role, outer_year, horizon, inner_year=None, *, bounded=False)` | Explicit library caller fits one admitted horizon pair after a unique claim; returns its immutable completion receipt, forecast rows and shared tail. |
| `DistributionFits.read(...)` | Replay verifies the same admission, claim, matrices and stored result without refitting; not a metadata-only read. |
| `distribution_oof.residual_pool(fits, role, outer_year, horizon, inner_year=None)` | C/tests obtain exact earlier-inner residuals joined to destination training labels, with identity/provenance and explicit unavailable states. |
| `distribution_oof.control_for_prediction(pool, histogram_document, point_prediction)` | Numerical consumer applies the declared shared residual pool to one forecast; returns mean-anchored histogram and nonnegative point controls, not calibrated probabilities. |

Dependencies are existing public native admission, fit evidence, immutable journal and CAS shard primitives, foundation hashing, fixed HGB model APIs, magnitude distribution arithmetic/payoff helpers and bounded stderr progress. NumPy/sklearn/threadpoolctl provide numerical work; no new library, store, transport, scheduler or generic estimator framework is introduced. Current consumers are C adapters, the fixed distribution worker and synthetic tests; the worker shares fit_evidence/load_fit_inputs and the numeric fit/publication APIs.

## Numeric and fit contract

Both no-fit guards precede numeric inspection and the explicit fitted operation. Training-all-null columns become zero in both matrices; partial NaNs retain native routing. Nonnegative training labels alone determine class support and empirical excesses over 20 percentage points, including zero at 20. Two observed bins are required; absent classes keep zero mass, with no smoothing or weighting. Installed libraries may inspect runtime state (for example threadpoolctl reads `/proc/self/maps`); numerical fitting is not described as I/O-free.
The classifier's classes, iterations and tree multiplicity must match the recipe/support. Its counts are observed; point iterations remain explicitly declared because the existing public point fitter exposes predictions only. Missing tail samples remain unresolved even at zero overflow mass; no synthetic tail, CDF or mean is invented.
Ordered raw training/prediction matrix hashes preserve nulls and event axes before fitting. The claim binds the exact B trial, plan, admission and matrix evidence; installed C sources/environment are included in the plan, so old seals cannot silently acquire new code. A unique fit claim precedes estimators; an interrupted claim cannot restart. Completion means both numerical arms returned, not that a supervised process or complete experiment succeeded.
Forecast rows and the shared tail use existing verified CAS sections; the immutable completion commits their descriptors and diagnostics. Forecast rows restore native evaluation order on read. One tail is stored per fit, not copied into every row; no prediction-by-residual Cartesian product is persisted. A repeated `fit` with an existing completion performs verified replay, not another estimator attempt; its no-fit guards still run first, while `read` is available under those guards. Replay revalidates admitted input identity and stored output contracts, never opens evaluation labels or refits. Bounded completion uses the closed `distribution_fitted.v2` envelope: the v1 fields plus required `execution` containing exactly `plan_id`, `worker` and `limits`. Every replay, including `read` and `fit(bounded=False)`, compares this binding and the required `fit-bound` journal marker against the admitted plan and fixed worker before reading result shards. Missing/changed binding or marker refuses with identity conflict, never refits. Legacy unbounded v1 retains its exact shape and requires no bounded marker; v1 cannot attest bounded execution or satisfy `fit(bounded=True)`. These consistency checks do not authenticate wholesale replacement of all evidence.
Inputs/matrices and projected result rows are materialized in memory. Existing shard/journal limits apply to stored evidence, not an end-to-end memory bound; estimator allocations and whole-job feasibility remain D/preflight responsibilities. Numerical pools use one thread. Stage start/end/elapsed/RSS and bounded progress use existing research logging; the in-process C path has no resource containment; the fixed child applies its CPU/resident-memory/affinity limits, while its caller owns wall limits and long-fit heartbeats.

## Causal residual contract

The versioned policy is pooled equal-weight earlier-OOF residuals per horizon, uniform finite-bin reconstruction, zero-clipped point support and the existing mean-anchored histogram control. `calibration_identity` remains `uncalibrated`: these empirical comparison controls do not calibrate classifier probabilities and perform no extra estimator fits. A learned probability calibrator requires an explicit later recipe and budget.
An outer destination requires its declared inner fits; an inner destination requires only its strictly earlier inner prefix in the same outer group. The first inner has no control pool. Missing or failed expected fits cannot silently disappear, and outer/self/future fits cannot become donors. All horizons retain their B identities rather than changing event completeness.
Only donor evaluation events present in the destination's centrally admitted training set contribute labels. Exclusions and coverage are explicit; no new label reader, threshold, holdout filter or residual-quality selection is added. Native admission owns protected membership and strict label availability. Each historical histogram mean uses that fit's own training-only tail, never the destination's later tail.
Pool provenance binds destination inputs/cutoff, plan/recipe/context, horizon and ordered donor result identities plus contributing keys/exclusions. Unresolved donor tails make the histogram pool unavailable without silently dropping rows; an otherwise usable point pool remains separate. Empty pools are unavailable, not fallback forecasts. The primary mean-matched control preserves zero atoms and refuses undefined zero/all-zero means; the point control records its actual post-clipping mean.

## Failure, storage and replay

| Condition | Outcome |
| --- | --- |
| Unsupported request, including a SIZE anchor that omits any native recipe horizon `(5, 3, 1)` | `INVALID_EXPERIMENT_SPEC` during plan preparation, before a distribution receipt or fit claim is published. |
| No-fit guard active | Original guard exception before fitting/admission work. |
| Invalid recipe/order/numeric input or unsupported fit selector/horizon | Typed invalid-spec refusal; omitted arguments retain Python `TypeError`. OOF provenance/selector mismatch instead uses identity conflict. |
| Degenerate support or malformed estimator output | Typed candidate failure; no partial successful fit receipt. |
| Changed input/implementation/result identity, missing completion, duplicate unfinished fit or incompatible donor | Identity conflict; no automatic repair, retry or silently reduced donor set. Histogram validation retains its native `CONTRACT_MISMATCH` data error. |
| No earlier/eligible residual observations or unresolved tail | Explicit unavailable control state; never a fabricated distribution. |
| Undefined mean-matching arithmetic | Existing magnitude arithmetic refusal, not a zero-valued fallback. |
| Fixed-child invalid resource/affinity scalar or axis, nonmapping header or invalid/missing recipe; memory/byte ceiling; known typed failure; OS affinity/unexpected exception | Compact INVALID_EXPERIMENT_SPEC; RESOURCE_LIMIT_EXCEEDED; original allowlisted code; RESOURCE_UNAVAILABLE respectively. Hard termination may emit no descriptor; the caller must refuse completion. |
| Resource, storage or unexpected programming failure | Native failure propagates; a committed claim remains unfinished. Published unreferenced shards can remain after interruption. |

Existing append transactions own unique journal associations, not whole-fit rollback. Completed in-memory estimators cannot be rolled back after a later failure; unfinished claims reserve work without asserting how many arms completed. No claim here establishes real-data feasibility, tradability, calibrated profitability or scientific success. Synthetic acceptance covers exact identity/replay, all horizons, tiny fixed fits, protected/future source boundaries, chronological poisoning, unavailable pools/tails and mean/support oracles.

## Fixed CAS fit worker

C and the installed `distribution_worker` share `distribution_fitted.validate_fit_output(recipe, matrices, labels, events, result)` before transport-only `publish_fit_output(store, rows, tail, diagnostics)`. Validation checks result schema/recipe, equal event/prediction counts and the existing probability, finite-point, training-tail and diagnostics contract; it returns ordered rows without storage or completion authority. `publish_fit_output` writes forecast/tail CAS sections and returns descriptors, never admission or journal completion. The internal worker receives only a bounded admitted manifest/identity/recipe/event-axis/horizon header, applies Linux CPU/affinity limits and the shared VmRSS watchdog before numerical imports (without RLIMIT_AS), runs the fixed pair and emits a compact CAS ArtifactRef or typed error. It opens no catalog or fresh outcomes and cannot mark a trial complete. Stdlib resource/JSON plus existing CAS/evidence/fit APIs suffice; no framework/dependency. Launching, wall containment and independently verified journal completion are caller responsibilities, not worker authority. The distribution plan explicitly fingerprints the fixed worker; worker-only source changes invalidate existing seals before new admission. `distribution_execution.run_distribution_fit` now supplies fixed bounded launch and compact response/exit verification; C selects it only with `bounded=True`, records its unique bounded binding and independently validates output before completion. Whole-job containment remains separate. [Worker protocol](README.md#fixed-cas-worker) includes failure boundaries.

## Run metadata and containment

`distribution_run_plan.DistributionRunPlan(trials, request)` is consumed by explicit local callers and synthetic tests. It detaches the existing closed D request and composes B `prepare_plan`, D7 bridge/benchmark readers, native snapshot resolution, source fingerprints, immutable journal and CAS sections. The native SIZE anchor must provide every horizon in the distribution recipe `(5, 3, 1)`; a subset anchor refuses during plan preparation before a distribution receipt or claim is published. Stdlib resource/signal and the shared VmRSS watchdog provide containment; no new dependency, framework, source reader, eligibility filter or holdout policy. Population remains centrally admitted eligible events within the frozen selected dataset, not source-wide completeness.

| API | Effects and contract |
| --- | --- |
| `plans()` / `preflight()` | Preflight first revalidates/detaches policy through the existing request validator, then reverifies B/native metadata, exact outer-year/alpha bridge coverage, required/optional benchmarks, opportunity cap and child-versus-parent memory ceiling. Read frozen bridge/benchmark artifacts and resolve the quote snapshot; no quote/target reads, fitting, registration, preparation or writes. Return detached request, snapshot, budget, coverage and source closure with a run-plan hash and `final_read_authority: none`; changing returned policy cannot change the instance's policy. Declared bounds are not measured feasibility. |
| `seal(clock=...)` / `admit()` | Seal B first, then append the D plan in the existing journal; a later D refusal can leave the B seal intact. Admission recomputes the plan and requires its canonical bytes to match the stored seal. No cross-seal rollback or automatic retry. Metadata roots bind this module plus the separately named fixed worker; a later executable subclass must seal its own entrypoint. |
| `record(slot, body=None, **options)` / `publish(name, rows)` | Explicit journal read/append or existing CAS section publication; these storage helpers do not authenticate successful execution. Slots/names are nonempty strings; appended bodies are dictionaries. Completion envelopes/descriptors use shared manifest-builder metadata validation on write/read. Before append, the completion ID must match the existing journal seal; missing/mismatched seals refuse without consuming the slot. This reads the verified seal, not fresh admission or report shards; collection still verifies admission and actual CAS bytes. Apply the shared resident-memory watchdog (not RLIMIT_AS), a soft CPU ceiling without raising inherited hard limits and the smaller parent/job wall limit; stop the watchdog and restore prior CPU/alarm state when execution unwinds. | Condition | Outcome |
| --- | --- |

| Containment wall deadline / resident-memory ceiling exceeded | `RESOURCE_LIMIT_EXCEEDED` / `MemoryError`; context cleanup restores CPU/alarm state and stops the shared watchdog when execution can unwind. Hard termination cannot promise cleanup. |
| Native artifact, journal, OS/signal or unexpected programming failure | Original failure propagates; existing records/objects are not erased, repaired or retried. |

The metadata class has no `run()` method or production activation. Tiny synthetic tests cover read-only preflight, required benchmark coverage, identity drift, real CAS verification, refusal propagation, standalone import/source closure and actual timeout/restoration in an isolated child process.

## D4 source-free scores and forecast report

This additive slice composes A's proper-scoring/payoff helpers, C's `control_for_prediction` and D3's existing cohort/cluster reporting. Current consumers are `distribution_pipeline` and synthetic tests; executable orchestration remains separate. Stdlib/NumPy and existing research progress cover the work; no new reader, transport, fit, calibrator, ledger or admission policy.

| API | Supplied inputs, output and effects |
| --- | --- |
| `distribution_scores.arm_forecasts(row, tail, pool, benchmark=None, *, receipt)` | C result row/tail and its completed receipt must match the causal pool destination (plan/admission, recipe/context/fold/inputs/budget, role/years/horizon) before numeric work; matching inputs yield histogram, same-mean and matched-point controls; optional admitted benchmark supplies incumbent draws, never gate-imputed magnitudes. |
| `distribution_scores.economic_forecast(value, bridge, decision, *, scale, round_trip_cost)` | Frozen bridge, per-share decision spot/premium, positive contracts×multiplier scale and nonnegative total-USD round-trip fees/slippage yield distinct P(net profit), net EV in USD and negative-exit diagnostics; unavailable arm/decision/tail yields None. |
| `distribution_scores.score_forecasts(result, pool, targets, *, outer_year, horizon)` | Admitted C outputs/pool plus a complete centrally supplied target-or-omission mapping yield per-event/arm raw scores. The result receipt must match that same pool binding, and its outer destination year/horizon must match the requested labels (outer role, no inner year) before row/target access, including empty inputs; mismatch or missing scope refuses `INVALID_EXPERIMENT_SPEC` before any output. No target reads; caller must freeze decisions before supplying outcomes. |
| `distribution_scores.profit_scores(intents, quotes)` | Frozen probabilities and already-costed total-USD entry/exit cash yield per-opportunity net-profit Brier scores, including unselected opportunities; supplied cash is signed plain int or finite float, not a funding/sign-policy check. Missing quote/forecast yields unknown, never a loss substitute. |
| `distribution_report.forecast_report(scores, opportunities, *, seed, resamples, block_days, block_origin, confidence)` | Single-pass scorer rows and common event/ticker/calendar metadata yield detached `distribution_forecast_report.v1`; no source/storage access, writes or fitting. |

Magnitudes and CRPS use percentage points; unscaled RPS uses 80 common thresholds, class loss is natural-log loss with explicit `"infinite"` for zero observed mass. Empirical controls retain atoms for CRPS and are binned only for common-bin scores. Fixed inclusive 5/10/20-point tail probabilities/counts are descriptive diagnostics, not proof of tail calibration. Unresolved tails retain bin scores but no full CRPS/economic forecast, even at zero overflow mass. Raw probabilities remain `uncalibrated`.
Forecast primary is h1 same-mean-minus-histogram CRPS (positive means histogram improvement); h3/5 are descriptive and never substitute for absent h1. The paired mean uses the common scoreable subset; full opportunity counts and per-arm exclusions remain explicit. Histogram absolute metrics use their own available subsets; finite log-loss mean is supplementary, never hides infinite losses. Matched-point scores remain secondary per-event output. Calendar/ticker intervals reuse D3's ratio-of-sums bootstrap, conditional on frozen fits without refitting or multiple-testing correction. No current-strategy, calibration, profitability or promotion claim follows.
Economics uses the identical bridge/costs for every arm; fees are converted once to per-share units, and quoted spread must not be charged twice. Receipt-to-pool matching checks supplied verified C evidence, not authentication of arbitrary rows or forged receipts; C retains CAS/source validation. Bridge/source provenance and execution economics remain caller-owned admitted inputs. Equal means imply equal bridge EV only when its zero clip is inactive; P(profit) can still differ. Post-clip negative residual exit values remain diagnostics, not silently repaired prices.

| Condition | Outcome |
| --- | --- |
| Malformed consumed report row, unsupported arm/horizon, duplicate or unknown event, invalid score/tail scalar, interval arithmetic failure, or unequal available-arm targets within an event/horizon | `INVALID_EXPERIMENT_SPEC`; no report publication. Available histogram/same-mean/matched-point observations must agree before the CRPS mask, including unresolved CRPS. Unavailable/missing-target placeholders remain coverage-only. Scorers otherwise require the producer shapes described above; structural/programming errors and underlying numeric/identity refusals retain their own contracts. |
| Explicit scale or round-trip cost fails the existing numeric predicate | Existing `INVALID_EXPERIMENT_SPEC` numeric refusal before missing arm/decision or unresolved-tail returns; valid unavailable economics remain None. |
| Invalid supplied cash scalar or profit probability, even when the other cash leg/quote/forecast is missing | Cash refuses `INVALID_EXPERIMENT_SPEC`; supplied probability retains numerical `CONTRACT_MISMATCH`. Each present cash leg/probability is checked; negative exit cash remains valid and unknown truth still withholds the Brier loss. |
| Missing control/target, unresolved CRPS or missing arm row | Explicit status/counts, no zero score or fabricated improvement; absent horizons remain absent. |
| Fewer than two scoreable calendar/ticker clusters | Unavailable conditional interval; point estimate may still exist. |

Scoring streams one event at a time with bounded progress; it materializes that event's empirical controls, not a persisted event×residual matrix. Report groups O(score rows) in memory and reuses bounded resampling progress; work is O(events log events + resamples×clusters) per horizon after scoring. This is not whole-job containment or a real-data feasibility claim. Synthetic oracles cover analytic CRPS, exact tail boundaries/atoms, missingness, linear-EV invariance with differing profit probability, after-cost truth and hand-aggregated cluster intervals.

## Causal outer pipeline

`distribution_pipeline` composes existing native target/quote readers, C verified fit receipts and earlier-inner pools, D4 scoring, D3 books/reports and D8 immutable CAS/journal publication. Stdlib and the installed platform cover this integration; no new reader, schema framework, fitting, eligibility rule or holdout policy. Consumers are explicit local callers and synthetic integration tests, not production activation.

Both calls require the existing CAS-verified D run seal. The live request must canonically match its sealed request, and `evaluate_outer` also requires the entire supplied plan to match that seal. Missing seals or changed/malformed policy/plan refuse `INVALID_EXPERIMENT_SPEC` before downstream readers, accumulator changes or publication. Each invocation consumes the detached sealed request/plan, so later caller mutation cannot change its decisions or report semantics. This small journal check does not repeat native eligibility/source admission; those remain the caller's existing prerequisite.

| API | Inputs, output and effects |
| --- | --- |
| `evaluate_outer(run, group, fits, results, plan, books, quotes, opportunities, sections, calendar)` | Caller-admitted outer group and all-horizon C results are bound to their causal pools by completed receipts. Reads shared D-1 quotes and frozen bridges, builds common-primary-arm strict-positive-net-EV h1 selections, then records every alpha's intents before reading D0/D+1 quotes or central evaluation targets. Only h1 drives selection; h3/5 remain diagnostic. Quote separation is by requested/returned keys: the existing native reader may scan wider pinned fragments before filtering, so this is not physical quote-byte isolation. The central target reader uses the source registration's frozen snapshot, holdout month and evaluation-label cutoff; exact target-or-omission coverage is required, never zero imputation. Missing decision quotes/control/tails abstain through the common primary mask. Missing outcomes preserve opportunities and unresolved book exposure, not survivor filtering. Shared alpha/bridge/cost semantics remain unchanged.

Malformed target coverage uses `INVALID_EXPERIMENT_SPEC`; receipt/pool mismatches and native data, CAS, journal or numeric failures propagate their owning refusals. Other later failures may leave intent/score artifacts and changed accumulators; discard failed invocation state, with no rollback, repair, retry or fitting fallback. Caller owns a single-use attempt, chronological admission, source closure and whole-job containment.

Per-call reuse keeps one calendar, all-alpha decision quotes and one event-indexed h1 result map. C pools and shared reports retain their documented memory bounds; accumulators scale with admitted opportunities/alphas/arms, not a persisted event-by-residual matrix. ## Explicit contained runner

`distribution_run.DistributionRun(trials, request)` extends D8 for explicit local library callers and synthetic tests. After inherited verification, its preflight requires the verified own registration's runner to equal `experiments/distribution_run.py`; a metadata or unrelated entrypoint refuses `EXPERIMENT_IDENTITY_CONFLICT` before a D seal or run claim. Preflight/seal binds the actual runner plus fixed worker closure, not the metadata-only class's roots; those seals are intentionally incompatible. `run(clock=None)` requires a dedicated Linux main-thread process and the explicit parent/job ceilings, installs D8 containment before admission, then runs one fresh attempt. Existing SystemClock, no-fit guards, native calendar, C/D6 bounded fit APIs, D9 pipeline and immutable journal/CAS helpers cover the need; no new framework, registration, source preparation, provider, ledger or eligibility policy.

Both fit guards precede fresh admission/fitting. A create-only start records the timestamp and remaining whole-job deadline, including bootstrap time; every group admits its earlier-inner folds before its outer fold and calls `DistributionFits.fit(..., bounded=True)` for each declared horizon. Each verified fit gets a compact run receipt. One run-local native calendar is shared, and D9 completes that group's frozen intents/outcomes/diagnostics before the next group's training admission. The runner returns a completed compact report only after all groups and sections succeed; no partial attempt is promoted or skipped.

| Condition | Outcome |
| --- | --- |
| Exact completion already present | Contained, verified read-only collection; no new fit, pricing, target read, CAS write or attempt deadline. Collection still has its own containment timer. |
| Changed seal/source or already-started unfinished attempt | Existing invalid-spec/identity refusal before new work; no automatic retry, deadline reset or reuse as a new bounded run. |
| Outer results lack any of the admitted `{1,3,5}` horizons or contain another horizon | `INVALID_EXPERIMENT_SPEC` before group evaluation or report publication; prior fit records remain, with no partial finalization. Native fitted receipts still own exact event-row validation. |
| Handled exception or interruption after start | Attempt a compact failure record with the original code or `INTERRUPTED`, preserve the committed prefix and re-raise the original exception unchanged. A secondary journal failure emits one fixed best-effort stderr diagnostic without exception details; diagnostic failure also cannot replace the original. Hard termination may prevent either record or diagnostic; unfinished claims remain reserved. |
| Parent/child resource exhaustion | Existing contained failure semantics; no successful completion or raised budget. Per-process bounds are not a measured aggregate-RSS guarantee. |

Standalone library preflight/seal/collect retain D8's caller-owned containment and artifact-read boundaries. `collect` verifies completed report sections, not every historical fit recursively. The runner does not certify statistical success, executable capacity, qualified real inputs or permission to read protected outcomes. Synthetic acceptance covers chronological all-alpha ordering, real journals/CAS/books, failure prefixes, forbidden retry, bounded-fit selection, source-seal separation and read-only replay under both no-fit guards.

The internal `_run_contained` shares an already-active caller deadline without resetting limits; callers otherwise use public `run`.

Books and quote accumulators use the detached sealed alpha roster and exist only inside the fresh invocation. A failed invocation discards that local state; the reserved attempt prevents reuse even through a new runner instance. Zero-funded reports retain unknown completeness and explicitly grant no risk sufficiency, promotion or strategy-superiority authority; diagnostic loss/drawdown flags alone are not successful-study evidence.

## Distribution operator

`python -m experiments.distribution_run` delegates to `distribution_cli.main(argv=None)` through a static import included in the registered source closure. Stdlib argparse and existing bounded metadata reader/renderer, native registration and D containment cover the need; no generic wrapper framework, preflight-receipt schema or new registry is introduced. Caller data roots stay explicit; the installed root is used solely for source fingerprints. [README](README.md#operator-lifecycle) defines every required input and action.

Preparation verifies a registered v1.7 all-horizon source plan, static distinct distribution runner policy and actual raw-pair fit/tree limits, then prepares v1.0 natively using the same pinned snapshot, scope, event roster and holdout month. It compares the recomputed population/holdouts rather than overwriting native fields. Registration alone reserves this owner using existing immutable transaction semantics and a fixed 16 MiB native evidence cap. Source preparation, bridge creation, benchmark materialization and SIZE execution are never hidden side effects. Preparation does not certify later run dependency coverage.

One dedicated main-thread containment scope covers bootstrap-adjusted metadata/catalog work, execution and bounded report rendering. Prepare/preflight/collect/report and the initial run completion probe open the existing catalog with SQLite `mode=ro`. Completed run replay collects there; only an absent completion permits closing/reopening writable and rebuilding/revalidating the run under the original deadline. Register/seal require writable catalogs. Replay never requests WAL mode or writes SQL/schema/CAS; native SQLite WAL reads may create/update coordination sidecars and must see committed WAL rows (no `immutable` shortcut). All actions require an existing artifact-store directory. Missing storage yields sanitized `RESOURCE_UNAVAILABLE`; missing/unreadable input files and malformed documents yield `INVALID_EXPERIMENT_SPEC`. Required spec fields missing/null are normalized only at explicit metadata parsing; other parser refusals and downstream semantic errors retain their original Problems. Raw CAS integrity failure retains `INTEGRITY_FAILED`; typed resource/holdout/identity failures pass through. Unexpected programming errors propagate. Normal unwind closes streams/catalog and restores limits. Signal setup/restoration failure can retain a stricter CPU soft ceiling; treat any failed process as terminal, never reusable. Bootstrap limits come from validated caller JSON, not an authenticated durable seal: later changed-policy refusal before started/fits does not retroactively impose sealed limits over pre-admission I/O.

There is no cross-action transaction or automatic repair: failed reservation can leave an unreferenced immutable CAS object, failed seal can leave its B prefix, and started runs retain claims and partial sections. Failure-journal I/O preserves the original execution exception and refusal classification; its fixed secondary diagnostic contains no raw storage detail. No completion or retry authority follows, even when the failure record is absent. Identical registration/seals replay normally; changed identities refuse. Collection never creates a catalog, trains, prices, reads evaluation targets or changes journals. JSON serialization is fully admitted against the existing 64 MiB output budget before stdout; inherited progress is redirected to stderr. Bounded source and report transport does not prove decoded memory or aggregate child/parent feasibility. Real synthetic subprocess tests exercise all seven commands, no-write preparation, bounded fitting and unchanged-journal report/replay.
