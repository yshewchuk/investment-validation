# Forecast-only distribution evaluation

## Purpose and boundaries

This component evaluates admitted absolute-magnitude forecasts without economic decisions. It reuses the existing magnitude representation/proper-score mathematics, native distribution fits and earlier-OOF controls. No option quotes, payoff-bridge application, EV, trade selector or funded book belongs to this evaluation path. The existing strategy implementation remains a separate consumer of compatible forecast primitives.

Native registration, dataset/feature qualification, training-label availability, event grouping, random/rolling holdouts and immutable fit receipts retain their existing owners. Source-free numerical helpers cannot authenticate arbitrary caller data, open labels or grant execution authority. The empirical-baseline adapter consumes freshly verified native training evidence and independently matches the completed fit claim, ordered matrices and disjoint event axes; an arbitrary list claiming causality is not admitted.

## Composed lifecycle

The neutral lifecycle composes these helpers into a dedicated contained prediction operator. Every admitted event is retained with explicit missingness, immutable source/request identity, native byte/resource bounds, consumed attempts and verified no-fit replay. Full forecast identity is persisted before admitted evaluation-target access. Strategy quote/bridge/economics/book prerequisites are not inherited. Synthetic lifecycle acceptance does not qualify an arbitrary real source or establish empirical accuracy.

The reports distinguish data availability from predictive interval coverage, and calibration diagnostics from fitted calibration. A frozen fit's paired uncertainty is not a refitted model-search experiment. Development results do not authorize protected holdout opening, empirical accuracy claims, production activation or a downstream strategy test.

## Prediction metadata lifecycle

`distribution_prediction_plan.PredictionPlan` validates and detaches a closed prediction-only request containing parent/whole-job limits, maximum admitted event count and explicit uncertainty settings. Preflight reuses native plan/source verification, requires all three horizons and unique outer event axes, and binds request, fit budget and installed source closure into a deterministic plan. Default roots explicitly include the freeze/replay evidence, training-baseline, evaluation and collection modules; subclasses declaring their own roots must include every execution and verification dependency. Seal persists that identity; admission rejects any later policy, resource, source or native-plan drift. It adds no quote, bridge, book or economic policy.

Prediction journal slots are create-only in a separate namespace, including identical retries. Bounded CAS sections preserve ordered positions and reverify bytes on reading. These primitives do not themselves execute, open targets, authenticate arbitrary section contents or provide completed-run collection. `PredictionRun` consumes them to publish all forecasts before targets, retain complete native receipts, consume failures and reverify stored evidence during collection. The CLI and direct `run` entrypoint enforce the declared limits in a dedicated contained process; the metadata interface alone is not an operator.

## Frozen forecast evidence

`PredictionRun._execute` calls `freeze_outer` after all bounded fits for an outer year. `distribution_prediction_evaluation` consumes `read_frozen_outer` before target access and on replay; the evidence helpers grant no source-read or lifecycle execution authority.

`freeze_outer` claims a create-only freeze slot, verifies the admitted complete 1/3/5 horizon roster and bounded completed fits before publishing any section, then records all forecast rows plus one logically shared control/baseline reference per horizon. Raw fitted laws, sealed numerical implementation and shared references fully specify the four prediction arms without storing an events-times-residuals matrix. No target reader is invoked. An interrupted or repeated freeze consumes its slot; later execution must abort rather than reuse partial state.

`read_frozen_outer` rebuilds native admission, completed fit, causal OOF and training-reference provenance, then checks every stored forecast/reference section and final all-horizon marker. Both entrypoints refuse non-string years with `INVALID_EXPERIMENT_SPEC` before admission or journaling. Malformed saved horizon entries and identity/layout changes refuse `EXPERIMENT_IDENTITY_CONFLICT` before section reads. Rehashing substituted control contents is insufficient. Replay performs no fits, writes or new outcome reads; evaluation and the runner retain ownership of source/target admission and the scoring/collection sequence.

Frozen schema `distribution_prediction_frozen.v2` binds `canonical_json_fragments.v1` and a fixed 65,536-character chunk size. The existing canonical serializer includes the entire nested reference, and existing position-indexed CAS sections store its lazy string fragments under unchanged shard caps. Replay compares each stored fragment directly to freshly reconstructed canonical text, without parsing/joining untrusted fragments; missing, extra, reordered or altered fragments refuse. Prior v1 single-row evidence is unsupported, not migrated or reused. Canonicalization retains O(total reference) text alongside native values; bounded persistence is not constant-memory execution. Each valid-Unicode fragment needs at most 384 KiB plus its small JSON wrapper, with actual shard bytes still checked by the existing writer.

## Admitted targets and evaluation

`PredictionRun._execute` calls `evaluate_outer` after the all-horizon freeze. `distribution_prediction_collection.report_evidence` consumes `read_evaluated_outer` during report reconstruction and completed collection; the runner retains attempt sequencing and containment ownership.

`evaluate_outer` consumes a create-only evaluation claim, freshly verifies frozen all-horizon evidence, then invokes the existing native bounded outer-target reader with the admitted normalized fold and source binding. The full native receipt, including physical inputs, cutoff, holdout identity and omissions, is validated and persisted alongside target rows. Exact event membership and explicit omission union are required; no quote, economic gate or trade choice filters the population. Every event/horizon receives all four proper-score and diagnostic status rows. Unresolved histogram tails retain valid bin scores but unavailable full-law interval/PIT diagnostics; missing targets and unavailable controls never become zero scores.

`read_evaluated_outer` revalidates native stored admission, forecasts, shared controls, target receipt/rows and final all-horizon markers, regenerates scores and diagnostics, and compares their stored CAS sections without fitting, writes or new source outcome reads. It prepares each shared empirical diagnostic reference once per horizon. Interval widths remain percentage points; PIT brackets are preserved unrandomized, not claimed uniform or fitted-calibrated. A failed evaluation is consumed and must be discarded, never retried in place.

Default `PredictionPlan` roots also include the evaluation module and its transitive scorer/diagnostic dependencies. Source-only evaluation changes invalidate the saved seal before either evaluation-start effects or replay's frozen-evidence reads. Explicit subclass root overrides remain responsible for their complete implementation closure; this library grants no execution or target-read authority by itself.

## Reporting supplied forecast evidence

`distribution_prediction_collection.report_evidence` calls `prediction_uncertainty`, which consumes `prediction_report` on regenerated native-admitted score rows. The report helper remains a source-free library API with no standalone CLI or execution authority; collection and the runner retain provenance, byte/resource admission and target-access ownership.

`distribution_prediction_report.prediction_report(scores, events)` consumes one pass of supplied score rows and the frozen event list (`event_id`, `ticker`, canonical `event_date`); it has no strategy, book, market or payoff dependency. Native callers still authenticate source/request/fit identity and bound input/output bytes. The helper checks unique events/row identities, consistent outer-year membership and observations across arms, and finite score/tail contracts. Missing rows remain explicit counts against the entire frozen population for every arm and horizon, including wholly absent horizons.

The shared row/event admission requires every retained payload, including nested provenance, to serialize with standard-library `json.dumps(..., allow_nan=False)` before copying; invalid keys/values, nonfinite numbers and recursive payloads refuse with `INVALID_EXPERIMENT_SPEC`. Present score/tail fields are validated for every status; only available rows require all fields. Missing-target tails retain boolean observations without comparing them to an absent target. Unknown provenance remains opaque and is preserved, not stripped or semantically authenticated; serialization adds a linear scan of retained payloads.

All four arms report scoreable-only CRPS/RPS/common-bin log-loss means and their sample counts; infinite log loss is never dropped from the overall mean. Fixed tail summaries pair predicted probability with realized frequency and count. Paired control-minus-histogram CRPS is positive for histogram improvement; only horizon-one same-mean is primary. Full-population deltas remain unavailable when any pair is missing; scoreable-only deltas retain exact paired and excluded event IDs. Detached, canonically ordered input rows and event metadata preserve supplied provenance and missingness for downstream diagnostics without granting provenance authority.

Malformed input/arithmetic refuses `INVALID_EXPERIMENT_SPEC` without mutation or partial results. The source-free helper has no cache, retry, writes, refitting or holdout reads. Index/sort plus fixed-arm/horizon summaries use O(rows log rows + events log events) time and O(rows + events) memory. Interval/PIT aggregation is supplied by the diagnostic-report helper and sealed conditional uncertainty by its separate reporting helper, both consumed by collection; this interface does not randomize PIT, fit calibration or choose promotion thresholds.

### Interval and PIT summaries

`distribution_prediction_collection.report_evidence` calls this helper on regenerated diagnostics that match the verified forecast/target evidence. It remains a source-free library without a standalone CLI or execution authority; native callers retain provenance and byte/resource admission.

`distribution_prediction_diagnostic_report.prediction_diagnostic_report(diagnostics, events)` uses the same neutral row/metadata admission as the score report. Available rows require four fixed equal-tail interval levels, inclusive coverage, width and both PIT bounds. Any present intervals on any status require the complete ordered levels, finite nonnegative geometry, exact width, nesting and boolean coverage; coverage agrees with the observation when one exists. Any present PIT bound must be numeric in [0, 1], and paired bounds must be ordered. Unavailable/missing-target rows may omit fields or retain valid partial fields. Each arm/horizon reports interval coverage **and width**, their count, and complete available/unavailable/missing-target/missing-row counts against frozen population. Unavailable diagnostics never become zero-width or uncovered observations.

Detached original rows retain exact PIT brackets, status reasons and supplied provenance. `pit_policy=brackets_only_unrandomized` deliberately claims neither a randomized PIT nor uniformity; deterministic event/horizon randomization needs a later sealed caller policy. The caller also binds diagnostic rows to matching score/forecast evidence. Complexity, typed failure and no-I/O/no-fit semantics match the score report. This interface authenticates no inputs, reads no targets, and supplies no fitted calibration, confidence claim or promotion cutoff.

### Conditional cluster uncertainty

`distribution_prediction_collection.report_evidence` calls this helper with the admitted prediction seal’s uncertainty policy and regenerated score rows. It remains a source-free library without a standalone CLI or execution authority; collection and the runner own provenance and enforced resource limits.

`distribution_prediction_uncertainty.prediction_uncertainty(scores, events, *, seed, resamples, block_days, block_origin, confidence)` validates and augments the score report once. Native callers must seal and bound the explicit policy before target reads; this pure helper cannot authenticate that seal. All CRPS contrasts and fixed probability-minus-observed tail calibration gaps receive ticker and occupied fixed-calendar-block percentile intervals. Calendar blocks use frozen `event_date`, never a trade decision clock. One draw from the full frozen cluster roster is reused across every arm/horizon/measurement, keeping whole events together despite differing scoreability.

Each interval uses an event-weighted ratio of sums, reports full/scoreable cluster counts and used/empty replicate counts, and is conditional on frozen fits and nonempty scoreable replicates. Fewer than two scoreable clusters is explicitly unavailable. Empty scoreable replicates never become zeros; percentiles use NumPy's explicit linear method, with no significance cutoff or fitted calibration. Interval-coverage/width uncertainty is not supplied by this slice. The fixed measurement family has O(events + resamples) workspace and O(resamples × occupied clusters) work per clustering, with bounded progress and no replicate-by-event matrix. Invalid policy/arithmetic refuses `INVALID_EXPERIMENT_SPEC` with no partial return, mutation, fit, read, retry or write; native containment remains the resource authority.

## Operator boundary

`distribution_prediction_preparation` consumes the native SIZE source-plan reader, fixed candidate fit-budget validation and native registration preparation. It requires the fixed prediction entrypoint, distinct owner identity and unchanged snapshot/scope/events/holdouts. `distribution_prediction_cli.main` routes explicit prepare/register/preflight/seal/run/collect/report actions through `DistributionTrials` and the prediction runner interface, using standard argparse/SQLite and the neutral containment/request contracts. It never creates a source or grants final-read authority.

All metadata inputs use the existing bounded native document reader. Both specs reject file inputs before registration/trials/runner access. Request parsing consumes the original parent/job deadline; an unfinished run alone reopens the catalog writable after a read-only completion probe. Completed replay uses `mode=ro`, not `immutable=1`, so committed live-WAL evidence remains visible. Input and artifact error categories remain distinct. Focused synthetic tests cover this boundary independently of the full native runner acceptance proof.

## Compact report evidence collection

`distribution_prediction_collection.report_evidence(run, fits)` freshly admits the prediction seal and native plan, takes event metadata from the verified source registration's `size_panel.context.target_events`, rejects duplicate metadata before filtering, and requires the entire sealed outer roster. Every outer year's `read_evaluated_outer` regenerates and compares bounded forecast/control/baseline/target/score/diagnostic evidence; collection independently requires exact four-arm/all-horizon row identities and matching observed targets. It reads stored admitted evidence, never new source outcomes, and performs no fitting or writes.

The returned `(groups, summaries)` binds each ordered outer year to its evaluation-record content hash. `forecast` and `diagnostics` summaries use explicit compact schemas, preserve numeric/count/conditional-uncertainty outputs and excluded-event counts, and omit duplicated raw rows/events and paired/excluded event-ID lists. Original verified sections and the native registration retain the full evidence; no whole-population row is manufactured for publication. `PredictionRun._execute` publishes these summaries through bounded CAS; `PredictionRun.collect` freshly reconstructs and compares them before returning verified summary values. This library adapter has no standalone CLI or independent execution authority.

Population/identity or malformed stored shape refuses `EXPERIMENT_IDENTITY_CONFLICT`; native/CAS/report/resource refusals propagate with no partial result, retry or repair. One source-metadata scan plus one evaluated replay per outer year precedes the existing bounded report calculations, retaining O(events + score rows + resamples) working storage. There is no cross-call cache; progress is bounded by outer years and the underlying replay/report stages.

Default `PredictionPlan` roots include the collection module and its transitive score, diagnostic-report and uncertainty implementations. Source-only changes invalidate the saved seal before evidence reconstruction or reporting; explicit subclass overrides remain responsible for their complete closure. The adapter reuses native admission/CAS readers and existing report APIs rather than adding another execution or storage framework.
