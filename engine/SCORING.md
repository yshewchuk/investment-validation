# Phase 1 — Model registry & scoring engine

`score(ticker, strategy, strike, expiry, as_of)` → expected PnL, win rate, a
confidence interval, and the evidence behind each number.

This document is the map. The reasoning lives in the module docstrings, which
are the primary source; this says how the pieces fit and which decisions were
made where the guide left a choice open.

---

## 1. The shape of an answer

Every score carries **two independent estimates, never averaged**:

| Layer | Question it answers | Where the number comes from |
|---|---|---|
| **Model** | What does the champion predict for *this* event? | Champion prediction → residual draws → empirically-calibrated payoff → the real entry cost from the real chain |
| **Analog** | What happened to trades like this one? | Matched historical trades from `engine.replay`, closed before the decision date, at the requested fill alpha |

When they disagree — opposite signs, or the model outside the analog CI — the
result carries `LAYER_DISAGREE` and both numbers survive. That is the one
situation the two layers exist to detect: a model extrapolating past its
evidence and a thin empirical set are indistinguishable once you take a mean.

## 2. Module map

```
engine/
  audit.py        leak discipline: FeatureVector + assert_causal, run on every call
  features.py     as-of feature vectors — panel path and live path, provably equal
  replay.py       structures × real chains → priced trades (THE shared path)
  build_trades.py driver: replay the universe, land it in Tier-2 `trades`
  payoff.py       predicted quantity → exit value, calibrated on real trades
  analogs.py      bucketing, the widening ladder, the bootstrap CI
  score.py        ScoreRequest / ScoreResult / Scorer / score_calendar
  calibrate.py    reliability, Brier, decile tables
  models/
    registry.py   the manifest and its four integrity rules
    registry.json champions (generated by training, edited by nothing else)
    training/     common.py (walk-forward) + one module per champion
```

Artifacts live in `data/models/*.joblib` — regenerable at a fixed seed, so they
are data, not code, and stay out of the public repo.

## 3. The three decisions the guide left open

The guide was written before Phase 0 shipped. Three things it assumes turned out
not to hold, and each was resolved deliberately rather than worked around.

### 3.1 Phase 1 owns the replay path

The guide sources the analog layer from "sim trades from the Phase 2 backtests"
and makes replay-equivalence a comparison against those backtests. Phase 2 does
not exist. Worse, the trade sets Phase 0 normalized carry a single worst-case
fill and no legs, so they cannot answer a question asked at mid — which is the
fill convention the entire program's positive verdict rests on.

So `engine/replay.py` is Phase 1's, and it is the path Phase 2's backtests will
be built from. Equivalence is then true by construction and *checked* anyway
(`checks/phase1_replay.py`), because "by construction" is a claim like any other.

The legacy S1/S2/S3 rows are kept and untouched. They are not relabelled as
CAL-P/STR-THRU/STR-RUNUP — Phase 0 refused to conflate them, and it was right:
S1 is a calendar *straddle* and S3 enters at a calendar T−14, neither of which
is the program structure it superficially resembles. The analog layer reads only
rows with `provenance == "engine.replay"`.

### 3.2 `implied_move` cannot be a model feature

The research size model's ten features include `implied_move`, the oquants
quoted implied move for the event being scored. It is genuinely pre-print
information — nothing leaks — and it is unavailable for any event that has not
happened yet, because it is read from the oquants moves file, which only lists
realized events.

A model trained on it scores every historical claim in this repo perfectly and
has nothing to read on the first morning it is asked to earn its keep.

`or_implied` (ORATS, from `daily_market` at the last pre-print close) is the live
equivalent and is what the champion uses. `engine.features.assert_live_available`
makes the substitution structural: the registry refuses to load a champion whose
feature list contains a live-unavailable feature. `size_model.compare_feature_sets`
measures what the swap costs, on the rows where both lists are complete, so the
decision is recorded as a number.

### 3.3 The payoff map is calibrated, not assumed

Turning "predicted |move| = 6.2%" into "expected P&L" needs a bridge. Pricing it
theoretically would require assuming how implied volatility behaves through a
print — the thing fifty experiments established cannot be assumed — and would
produce a number with no way to check it.

Instead `engine/payoff.py` fits `exit_value/spot ≈ a + b · driver` on real
replayed trades at the same fill alpha, and applies it to the **real entry cost
from the real chain**. The fit uses only trades that had *closed* before the
decision date, so a payoff map used to score January 2021 knows nothing about how
2021 turned out.

The driver differs by structure, and the difference is the structure's thesis:

| Strategy | Driver | Why |
|---|---|---|
| STR-THRU | `abs_move` | Held through the print — the realized move *is* the trade |
| STR-RUNUP | `im_t1` | Sold before the print, so the realized move is irrelevant by construction; what it is worth at exit is the implied move being quoted then |
| CAL-P | — | No payoff map, because there is no validated evidence to calibrate one against |

## 4. Leak discipline, and the one distinction that carries it

Every feature value carries an as-of stamp; `assert_causal` runs on every
scoring call, not only in tests, and raises rather than warns.

The distinction that does the real work is **which features are legitimate at
which decision date**:

- `EVENT_HISTORY_FEATURES` depend only on the ticker's *prior events*, so they
  are known at any date before the print.
- The panel's **market-state block** (`or_implied`, `dist_high`, `spy_vol20`,
  the market cap) is read at the last pre-print close.

For STR-THRU, which enters at that close, the market block is contemporaneous
and entirely legitimate. For STR-RUNUP, which enters fourteen trading days
earlier, the same values would be a fortnight of hindsight — and they would
flatter the entry-timing model precisely where the strategy's whole claimed edge
lives.

So the scorer supplies the market block **only when the entry is the decision
close**. A model that needs it at an earlier entry reports `MISSING_FEATURES` and
declines to score, which is correct: it is the wrong model for that date.
STR-RUNUP is driven by `implied_t1`, whose features are as-of the entry by
construction.

Two further causality rules, each enforced and tested:

- **Analogs** must have *closed* before the decision date (`engine/analogs.py`).
- **Payoff maps** are fitted only on trades closed before it (`engine/payoff.py`).

## 5. The registry

Champions are looked up by `(strategy, role)`. Nothing outside
`engine/models/` opens an artifact. Four rules are enforced at load:

1. **One champion per (strategy, role).** Two is an unresolved promotion, not a
   tie-break to settle at call time.
2. **The artifact hash matches the manifest.** A model retrained in place while
   its recorded metrics stay put makes every downstream number a claim about a
   file nobody can identify.
3. **The feature list matches the artifact.** A permuted list scores on permuted
   inputs and returns plausible nonsense.
4. **Every feature is live-servable** (§3.2).

Roles: `size` (predicted |move|), `implied_t1` (implied move at the last
pre-print close), `gate` (predicted mid-fill return — the selection signal).

Registry edits happen through `register()` at training time, and after this
phase through Phase 2's promotion protocol. Promotion is atomic: registering a
champion demotes the incumbent in the same write, so the file never passes
through a two-champion state.

## 6. Hard constraints the code enforces

- **CAL-P is not scored.** It returns `UNVALIDATED_STRUCTURE` and no numbers.
  The +2.0%/trade figure belongs to EXP-046b, which tested straddle legs entered
  at T−14 and unwound *before* the print — a different trade. No payoff map, no
  gate, no champion. Phase 2 backlog items 1–2 must run first.
- **Non-ATM strikes are labelled `EXTRAPOLATED`** until the moneyness edge-decay
  experiment is promoted. The flag survives into every output.
- **No network.** Scoring reads Tier 2/3 and the registry.
- **Determinism.** `(request, snapshot)` → a byte-identical `ScoreResult`. The
  bootstrap seed is derived from the snapshot hash and the request, so the same
  question against the same data gives the same interval on any machine.
- **Never interpolate a missing price.** A missing chain is `NO_CHAIN` and the
  analog layer answers alone.
- **No invented intervals.** An analog set too thin to support a CI reports
  `THIN_ANALOGS` and no CI.

## 7. Running it

```bash
# rebuild the trade set (~35 min over the full universe)
python3 -m engine.build_trades

# train and register the champions
python3 -m engine.models.training.train_all

# acceptance
python3 checks/phase1_checks.py
python3 checks/phase1_replay.py          # the load-bearing equivalence, alone
python3 checks/phase1_calibration.py     # calibration, alone
```

```python
from engine.score import score, score_calendar
from engine.fills import MID, WORST, BEST

result = score("AAPL", "STR-THRU", as_of="2026-01-28", fill=MID)
board = score_calendar(horizon_days=21)     # the dashboard's input
```

## 8. Known limits

Stated so nobody has to rediscover them.

- **Chain coverage bounds the evidence.** Of 98,705 calendar events with a known
  session, STR-THRU can be replayed on 17,754 (18%) and STR-RUNUP on 6,943 (7%).
  The binding constraint is post-print exit chains for STR-THRU and T−14 entry
  chains for STR-RUNUP. `ReplayResult.coverage` quotes the priced share against
  the *full* planned universe rather than the chain-covered subset, so the gap
  stays visible.
- **The analog layer is ATM-centric**, because the evidence is. Non-ATM scores
  are labelled, not suppressed.
- **The payoff map is a straight line in one variable.** With a few thousand
  trades and a lumpy edge, a flexible fit would model 2022 and 2024 rather than
  the mechanism. Revisit when the Sep-1 pull enlarges the sample.
- **STR-RUNUP's entry offset is fixed at −14 trading days.** Choosing it per
  predicted-run-up decile is Phase 2 backlog item 3; `implied_t1` pools decision
  days with `days_before_print` as a feature specifically so that experiment has
  a model to work with.
